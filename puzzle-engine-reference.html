1. Word & Language (8 Mechanics)

01

Word Search

Word & Language
Core Mechanic

A grid of letters contains a list of target words hidden in straight lines running in any of up to 8 directions (horizontal, vertical, diagonal — forward or backward). The solver scans the grid and traces each word from start letter to end letter.

Cognitive Skill

Visual pattern-matching and sustained scanning attention — spotting a hidden shape in noise.

Difficulty Levers

Grid dimensions; ratio of grid cells to letters-in-words (more filler = harder); number of allowed directions (straight-only vs. +diagonal vs. +backward); word count/length; visual similarity between filler and real letters; whether words may cross/share letters.

Generic Data Template
json 
{
  "items": [{ "answer": "TERM1" }, { "answer": "TERM2" }, { "answer": "TERM3" }],
  "config": {
    "rows": 15, "cols": 15,
    "directions": ["E","W","N","S","NE","NW","SE","SW"],
    "allow_backwards": true, "allow_overlap": true,
    "max_placement_attempts": 200
  }
}
Generation Algorithm
pseudocode 
normalize(items) -> strip spaces/punctuation, uppercase each answer
sort items by answer length DESC          // place hardest/longest first
grid_size = max(config.rows/cols, longest_answer_length)
grid = empty rows x cols matrix

for item in items:
  placed = false
  for attempt in 1..max_placement_attempts:
    dir = random_choice(config.directions)
    start = random_cell_such_that(word fits in bounds along dir)
    if every cell along path is EITHER empty OR already has the matching letter:
        write letters into grid along path
        record solution[item.answer] = {start, dir, len}
        placed = true; break
  if not placed:
      grow grid_size by 1 and retry item, OR drop item and flag as unplaced

for each empty cell: fill with random letter (weighted by letter-frequency table)

// integrity pass
rescan all rows/cols/diagonals for accidental exact matches of OTHER list words
  or blocklisted words -> if found, re-roll offending filler letters and rescan

output: { grid, solution_key, unplaced_items }
Edge Cases & Gotchas
  • Grid must be at least as large as the longest word in both dimensions, or placement is impossible from the start.
  • No retry cap can loop forever on dense grids — always bound attempts with a grow-grid/drop-word fallback.
  • Random filler letters can accidentally spell an unintended real word (or profanity) — needs a post-fill validation rescan.
  • Multi-word phrases need an explicit policy (strip spaces vs. reject) since cells hold single letters.
02

Crossword

Word & Language
Core Mechanic

A grid of white and black squares holds interlocking Across/Down answers; every white cell belongs to exactly one Across and one Down word, agreeing on the shared letter at intersections. Numbered clues correspond to each entry's start square.

Cognitive Skill

Constraint-satisfaction deduction — inferring an unknown word from a clue plus letters already forced by intersecting answers.

Difficulty Levers

Grid size; black-square density (fewer blacks = harder, more interlock required); average word length; crossings per word; clue directness (definition vs. wordplay); whether 180° rotational symmetry is enforced.

Generic Data Template
json 
{
  "items": [
    { "answer": "TERM1", "clue": "clue1" },
    { "answer": "TERM2", "clue": "clue2" },
    { "answer": "TERM3", "clue": "clue3" }
  ],
  "config": { "max_rows": 15, "max_cols": 15, "enforce_symmetry": false, "min_word_length": 3 }
}
Generation Algorithm
pseudocode 
words = normalize(items)  // uppercase, strip spaces/punctuation, drop len<3
sort words by length DESC
grid = empty max_rows x max_cols (all black)
place words[0] across the center row; mark cells white/lettered
unplaced = words[1:]

loop until unplaced empty or no progress:
  for word in unplaced (try longest first):
    candidates = []
    for placed_word in already_placed:
      for i, letter in enumerate(word):
        for j, letter2 in enumerate(placed_word.text):
          if letter == letter2:
              candidates.append(perpendicular placement crossing at that cell)
    shuffle(candidates)  // or rank by resulting interlock score
    for placement in candidates:
      if VALID(placement): commit(placement); mark word placed; break
  if no word was placed this pass: break  // stuck - needs backtrack/resize

VALID(placement) checks:
  - every overlapping cell matches the same literal letter (no contradictions)
  - cell before start / after end is black/border (no unintended run-on word)
  - resulting word length within [min_word_length, max bound]
  - no adjacent parallel word created with zero gap
  - grid stays within max_rows/max_cols

// finishing
mark all untouched cells black
if enforce_symmetry: mirror black/white pattern under 180 deg rotation, re-verify
number cells: row-major scan; numbers if cell starts an Across (no white cell
  to its left) OR a Down entry (no white cell above)
final check: every white cell touches >=1 across AND >=1 down entry >=3 letters,
  grid is one connected region (flood-fill check)

output: { grid, across_clues, down_clues, numbering, unplaced_items }
Edge Cases & Gotchas
  • Greedy placement without backtracking frequently dead-ends before all words are placed — needs real backtracking or simulated annealing, not one greedy pass.
  • Small/low-overlap topic vocab may never fully interlock — need a fallback (accept partial placement + report dropped words, or pad with filler words).
  • A common bug: checking word-level equality instead of per-character equality at the intersection.
  • Enforcing rotational symmetry is a major constraint multiplier — usually worth relaxing for auto-generation from arbitrary data.
03

Wordle

Word & Language
Core Mechanic

The solver has a fixed number of guesses (classically 6) to identify a secret word of fixed length (classically 5). Each guess must be a valid dictionary word; letters are colored green (correct position), yellow (present elsewhere, respecting duplicate-letter counts), or gray (absent).

Cognitive Skill

Deductive elimination under a limited-attempt budget — balancing information-gain guesses against committing to a final answer.

Difficulty Levers

Word length; number of allowed guesses; target word obscurity/frequency; duplicate letters in the target; strictness of guess validation; "hard mode" requiring reuse of revealed clues.

Generic Data Template
json 
{
  "items": [{ "answer": "term1" }],
  "config": {
    "word_length": 5, "max_guesses": 6,
    "guess_dictionary": ["term1", "otherword1", "otherword2"]
  }
}
Generation Algorithm
pseudocode 
eligible = filter(items.answer, len == word_length AND alphabetic-only)
if eligible empty: reduce/raise word_length or reject config
target = random_choice(eligible).answer.upper()

// validation pool MUST be broader than the puzzle's own item list, or the
// answer is trivially the only word of that length available
guess_set = union(config.guess_dictionary, eligible) -> dedupe

score_guess(guess, target):
    result = [GRAY] * len(guess)
    remaining = letter_counts(target)
    // pass 1: greens
    for i in range(len(guess)):
        if guess[i] == target[i]:
            result[i] = GREEN; remaining[guess[i]] -= 1
    // pass 2: yellows/grays using leftover counts only
    for i in range(len(guess)):
        if result[i] == GREEN: continue
        if remaining[guess[i]] > 0:
            result[i] = YELLOW; remaining[guess[i]] -= 1
        else:
            result[i] = GRAY
    return result

output: { target, word_length, max_guesses, guess_set, score_guess_fn }
Edge Cases & Gotchas
  • The two-pass duplicate-letter scoring is essential — a naive "is this letter anywhere in the target" check is wrong whenever target or guess has repeated letters. This is the #1 bug in homemade clones.
  • Guess validation needs a real dictionary superset, or the game becomes solvable by elimination almost immediately with a small custom vocabulary.
  • Arbitrary datasets rarely have many words of exactly one fixed length — pick word_length dynamically per puzzle, or accept a shrunken eligible pool.
  • Non-alphabetic tokens or multi-word phrases must be filtered before becoming candidate answers.
04

Word Snake

Word & Language
Research Note: "Word Snake" covers two common formats: (a) a word-search variant where hidden words follow a bendable orthogonal path, and (b) a chain of words where each word's last letter equals the next word's first letter, laid out as one winding path. Variant (b) is used below since it's the more naturally generatable from an arbitrary list of terms.
Core Mechanic

A sequence of words is chained so each word's last letter equals the next word's first letter (e.g. PYTHON -> NUMPY -> YIELD), drawn as one continuous winding path with each junction letter sharing a single cell where the path turns a corner.

Cognitive Skill

Sequential associative recall plus a lightweight constraint — recognizing a word that starts with a forced letter.

Difficulty Levers

Chain length; variance in word length; number of overlapping letters required at each junction; whether clues are given per word; complexity of the snake's path.

Generic Data Template
json 
{
  "items": [
    { "answer": "term1", "clue": "clue1" },
    { "answer": "termB", "clue": "clueB" },
    { "answer": "beta",  "clue": "clueC" }
  ],
  "config": { "min_chain_length": 5, "grid_width": 12 }
}
// items do not need to already be in chainable order - the generator
// must discover/order a valid subset.
Generation Algorithm
pseudocode 
words = normalize(items)  // uppercase, strip non-letters
build directed graph G: edge word_A -> word_B if last_letter(A) == first_letter(B)

// finding the longest usable chain is longest-path-in-a-digraph (NP-hard)
if len(words) <= ~25:
    best_chain = DFS_with_memo(G) maximizing nodes visited without repeats
else:
    best_chain = greedy_nearest_neighbor(G) + bounded local repair passes

if len(best_chain) < config.min_chain_length:
    report insufficient_data (dataset's first/last letters don't connect)

// lay chain into a grid as a winding path
cursor = (0,0); direction = RIGHT
for word in best_chain:
    for letter in word (skip first letter after the first word - shared junction):
        place letter at cursor; advance cursor along direction
    at junction (word end): turn direction 90 deg (alternate row/turn/row...)
    ensure new segment doesn't collide with placed non-junction cells (retry
    turn direction/offset if collision detected)

output: { grid, ordered_chain, clues, junction_coords, dropped_items }
Edge Cases & Gotchas
  • Most arbitrary vocabulary lists will not naturally chain by first/last letter — the generator must drop unchainable items and report how many made it in.
  • True longest-path search is NP-hard; use greedy-plus-repair heuristics for large item counts and cap runtime.
  • Greedy first-match chaining can dead-end early — prefer backtracking/beam search over pure greedy.
  • Routing the winding path needs collision detection at every turn; an overlap requires an alternate offset or direction.
05

Anagram

Word & Language
Core Mechanic

The solver is shown a scrambled arrangement of a word's letters and must rearrange them back into the correct, valid word — usually aided by a clue.

Cognitive Skill

Combinatorial pattern search — mentally testing letter groupings against known vocabulary.

Difficulty Levers

Word length; letter repetition (reduces meaningfully different scrambles); whether a clue is provided; single word vs. multi-word phrase; how scrambled the shuffle is; number of alternate valid solutions.

Generic Data Template
json 
{
  "items": [{ "answer": "term1", "clue": "clue1" }],
  "config": { "min_length": 4, "allow_multi_word": false }
}
Generation Algorithm
pseudocode 
for item in items:
    letters = strip_spaces_and_punctuation(item.answer.upper())
    if len(letters) < config.min_length: skip item

    scrambled = letters
    attempts = 0
    while (scrambled == letters OR too_similar(scrambled, letters)) and attempts < 50:
        scrambled = fisher_yates_shuffle(letters)
        attempts += 1
    if attempts == 50: skip item  // degenerate word (e.g. all identical letters)

    // optional fairness check
    if dictionary_available:
        other_valid_answers = find_all_dictionary_words_matching_letter_multiset(letters)
        ambiguous = len(other_valid_answers) > 1

    output_item = { scrambled, answer: item.answer, clue: item.clue, ambiguous, other_valid_answers }
Edge Cases & Gotchas
  • Very short words (≤3 letters) often have only one or two reorderings, making the puzzle trivial or impossible to scramble — enforce a minimum length.
  • Heavy letter repetition (e.g. "LULL") can make every shuffle look identical — bounded retry-then-skip fallback needed.
  • Anagram ambiguity is common (letters of "EAT" also spell "ATE"/"TEA") — decide a policy: accept any dictionary-valid answer, or lock to one canonical answer.
  • Multi-word phrases raise the question of whether space positions are given — must be an explicit config choice.
06

Cryptogram

Word & Language
Core Mechanic

A quote or short passage is encoded with a monoalphabetic substitution cipher — each plaintext letter consistently replaced by one other letter (a full bijection), while spacing/punctuation is preserved. The solver uses frequency analysis and pattern recognition to reconstruct the key.

Cognitive Skill

Frequency analysis and pattern-based deduction — classic codebreaking.

Difficulty Levers

Text length (more letters = easier frequency analysis); vocabulary obscurity; number of letters pre-revealed as free hints; whether word-length/spacing pattern is preserved or stripped.

Generic Data Template
json 
{
  "items": [{ "text": "quote or fact text here", "source": "attribution (optional)" }],
  "config": { "reveal_count": 2 }
}
Generation Algorithm
pseudocode 
plaintext = item.text.upper()

// build a full 26-letter derangement (no letter maps to itself)
mapping = random_permutation(A..Z)
while any(mapping[c] == c for c in A..Z):
    fix_points = find(mapping[c] == c)
    for c in fix_points: swap mapping[c] with mapping[random_other_letter]

ciphertext = ""
for ch in plaintext:
    if ch is A-Z: ciphertext += mapping[ch]
    else: ciphertext += ch   // spaces, punctuation, digits pass through unchanged

// optional freebies: reveal mapping for the most frequent ciphertext letter(s)
revealed = top_N_most_frequent_letters(ciphertext, config.reveal_count)

output: { ciphertext, mapping (solution key), plaintext, source, revealed }
Edge Cases & Gotchas
  • Must guarantee a true bijection — independent random assignment without tracking used targets produces collisions, making some ciphertext letters undecodable.
  • A plain random shuffle can still produce fixed points (letter maps to itself) — needs an explicit derangement/repair step.
  • Non-letter characters (digits, symbols — common in formulas) must pass through unmodified.
  • Very short source texts (roughly under 40-50 letters) are often unsolvable by frequency analysis alone — enforce a minimum length or lean on revealed-letter hints.
07

Inner/Outer Word

Word & Language
Research Note: No single trademarked name dominates this format; it's most commonly called a "hidden word" puzzle, with historical roots in the classic "logogriph."
Core Mechanic

A longer "outer" word contains a shorter "inner" word spelled by a contiguous run of its letters (e.g. CAT hidden in s-CAT-ter). The solver locates/extracts the hidden inner word, sometimes guided by a clue defining it rather than seeing it directly.

Cognitive Skill

Substring pattern recognition — spotting a smaller familiar shape camouflaged inside a bigger one.

Difficulty Levers

Length gap between outer and inner word; number of hidden words surfaced per outer word; whether the inner word's position is hinted; whether the outer word itself must also be guessed from a clue; commonness of the inner word.

Generic Data Template
json 
{
  "items": [{ "outer": "term1", "outer_clue": "clue1" }],
  "config": { "min_inner_length": 3, "max_hits_per_outer": 1 }
}
Generation Algorithm
pseudocode 
for item in items:
    outer = strip_non_letters(item.outer.upper())
    hits = []
    for start in range(len(outer)):
        for end in range(start + config.min_inner_length, len(outer)):  // end < len(outer)
            substr = outer[start:end]
            if dictionary_contains(substr):
                hits.append({ inner: substr, start, end })

    if hits is empty: skip item (flag: no hidden word found)

    // prefer longer inner words and more central (non-edge) positions for harder mode
    hits.sort_by(key = (-length, distance_from_center))
    chosen = hits[0:config.max_hits_per_outer]

    for hit in chosen:
        inner_clue = dictionary_lookup_definition(hit.inner) or "a hidden word"

    output_item = { outer: item.outer, outer_clue: item.outer_clue, hidden_words: chosen }
Edge Cases & Gotchas
  • Requires an independent dictionary/wordlist to validate substrings — many outer words will contain zero valid hidden words, so graceful skip is required.
  • A single outer word often contains several valid inner words at multiple lengths — needs explicit rules for how many to surface and a minimum length to avoid noisy 2-letter hits.
  • If outer terms are multi-word phrases, decide explicitly whether the search may span the removed space between words.
  • Domain-specific outer vocabulary is fine — the inner word found will usually be an unrelated common word, which is expected, not a bug.
08

Same-word Fill-in-the-Blank

Word & Language
Research Note: No standardized commercial name exists for this exact format. Closest recognized categories: "cloze" exercises and educational homograph/multiple-meaning fill-in worksheets.
Core Mechanic

Several separate sentences are each shown with one blank; exactly one word — often used in a different sense or part of speech each time — correctly completes every sentence.

Cognitive Skill

Lateral, convergent reasoning — triangulating one answer from multiple differently-flavored contexts, often exploiting polysemy/homonymy.

Difficulty Levers

Number of sentences/blanks; semantic/part-of-speech distance between required senses; obscurity of the shared word; whether sentences are revealed all at once or one-by-one on failed guesses.

Generic Data Template
json 
{
  "items": [{
    "answer": "term1",
    "sentences": [
      "sentence1 with a _____ in it",
      "a different sentence2 also needing _____",
      "sentence3, unrelated context, still needs _____"
    ]
  }],
  "config": { "blank_marker": "_____" }
}
Generation Algorithm
pseudocode 
// Mode A - curated dataset already supplies multiple sentences per answer (preferred)
for item in items:
    assert item.sentences.length >= 2
    for s in item.sentences:
        assert s.count(config.blank_marker) == 1
        assert item.answer.lower() not in remove_marker(s).lower()   // no spoiler leak
    shuffle(item.sentences)   // presentation order
    output_item = item

// Mode B - flat term/definition datasets with no pre-written sentences:
// group items by identical `answer` text (true homographs already present in data)
groups = group_by(items, key = item.answer.lower())
for group in groups where len(group) >= 2:
    sentences = []
    for entry in group:
        sentences.append(templated_sentence(entry.clue))  // vary templates,
                                                            // avoid literal "the word meaning X is ___"
    output_item = { answer: group.answer, sentences }
for items not in any group of size >= 2: report as unusable for this puzzle type
Edge Cases & Gotchas
  • Core bottleneck: this format needs multiple example sentences per answer word, which flat term->definition datasets rarely provide — expect to fall back to curated input or an LLM-assisted sentence-authoring step.
  • Auto-synthesized sentences built directly from definitions risk being unnatural or self-revealing — vary sentence templates and avoid echoing the definition verbatim.
  • Multi-solution risk: if a different common word also fits one sentence in isolation, the puzzle becomes ambiguous — spot-check each sentence individually.
  • Ensure the answer word (or an obvious inflection) doesn't appear elsewhere in the sentence text, which would spoil the answer.

09

Sudoku

Grid & Spatial Logic
Core Mechanic

A 9x9 grid divided into nine 3x3 boxes is partially filled with digits 1-9; the player fills every empty cell so each row, column, and box contains every digit exactly once, using elimination across the intersecting constraints.

Cognitive Skill

Deductive constraint-satisfaction — narrowing possibilities through pure logic until each cell is forced.

Difficulty Levers

Number of givens (17 is the proven minimum for a unique solution); symmetry/placement pattern of givens; which solving techniques are required (naked singles → pairs/triples → X-wing/swordfish); grid variant (4x4/6x6, 16x16, jigsaw box shapes).

Generic Data Template
json 
{
  "puzzleType": "sudoku", "gridSize": 9, "boxDims": [3,3],
  "symbolSet": ["itemA","itemB","itemC","itemD","itemE","itemF","itemG","itemH","itemI"],
  "generationParams": { "givenCount": 30, "symmetry": "rotational180", "targetDifficulty": "medium" },
  "revealOverlay": { "cells": [[0,0],[0,1],[0,2]], "onCompleteFact": "attributeA relates to attributeB because ..." }
}
// Sudoku is inherently numeric/spatial, not data-driven - topic content is
// carried by bijectively relabeling digits 1-9 with 9 dataset items, or by
// revealing a fact when specific marked cells are completed.
Generation Algorithm
pseudocode 
fullGrid = solve(emptyGrid) via randomized backtracking (shuffle candidate order)
puzzle = copy(fullGrid)
cellsToTry = shuffle(all 81 positions), optionally paired by chosen symmetry

for cell(s) in cellsToTry:
     remove value(s) from puzzle
     count = countSolutions(puzzle, limit=2)   // backtracking solver, stop early at 2
     if count != 1: restore value(s)
   until target givenCount reached or no more safe removals

(optional) run a human-technique solver to classify difficulty by hardest
  technique required; if too easy/hard, adjust removal set and re-verify

output: puzzle grid + solution grid
Edge Cases & Gotchas
  • Removing cells without a uniqueness-check solver is the #1 bug — naive random removal frequently produces multi-solution puzzles.
  • Difficulty is not the same as given-count — two 28-given puzzles can differ wildly by required technique.
  • Symmetric removal patterns constrain which cells can be removed together — re-verify uniqueness after each symmetric pair.
  • Symbol substitution for topic data must preserve a strict 1:1 mapping — duplicate items break the puzzle.
10

Nonogram

Grid & Spatial Logic
Core Mechanic

A grid is filled/left-blank so each row and column matches its clue — a sequence of numbers giving the lengths of consecutive filled runs, in order, separated by at least one blank. Cross-referencing row/column clues reveals a hidden picture.

Cognitive Skill

Constraint propagation across two intersecting axes, with the payoff of a hidden image "revealing" itself.

Difficulty Levers

Grid size; image complexity/fragmentation (fragmented images are harder and more ambiguity-prone); number of colors; whether solvable by pure line-logic or requires trial-and-error/contradiction.

Generic Data Template
json 
{
  "puzzleType": "nonogram", "gridSize": { "rows": 10, "cols": 10 },
  "source": { "mode": "textRender", "revealText": "TERMA", "font": "pixel5x7" },
  "sourceAlt": {
    "mode": "dataMatrix", "items": ["itemA","itemB","itemC"],
    "attributes": ["attr1","attr2","attr3"], "matrix": [[1,0,1],[0,1,0],[1,1,0]]
  },
  "palette": ["#000000"]
}
// Topic-driven two ways: render a keyword into a pixel-font bitmap, or use a
// real items-x-attributes boolean matrix directly as the grid so solving it
// literally reconstructs a true/false fact table.
Generation Algorithm
pseudocode 
1. Obtain a boolean grid (bitmap): render revealText via pixel font, OR use
   dataMatrix directly, OR random-generate with a target fill ratio
2. Derive rowClues[i] and colClues[j] by scanning each line and recording
   run lengths of consecutive filled cells
3. Verify uniqueness: run a line-solver (iteratively compute forced cells per
   row/col from clues, propagate) until stable
   if grid fully determined -> unique, done
   else run backtracking search counting solutions (limit=2)
   if >1 solution: perturb grid (flip a small cluster of cells), retry from step 2
4. Output rowClues, colClues, and solution grid
Edge Cases & Gotchas
  • Clue generation from a bitmap is trivial, but the clue set doesn't always uniquely determine that bitmap — always solver-verify, don't assume.
  • Highly symmetric or blocky/checkerboard patterns are most prone to ambiguous multiple solutions.
  • All-blank or all-filled lines produce a "0" clue or a single full-length run — must be handled explicitly.
  • Multi-color nonograms need color-tagged clue blocks and an explicit adjacency rule for same-color runs.
11

Minesweeper

Grid & Spatial Logic
Core Mechanic

A grid hides a set number of mines; revealing a safe cell shows a count of mines among its 8 neighbors (0 triggers a flood-fill reveal). The player flags suspected mines and deduces safe cells from the numbers, winning when all non-mine cells are revealed.

Cognitive Skill

Local constraint deduction under risk — reading overlapping number constraints to prove safety.

Difficulty Levers

Grid dimensions; mine density; size of the guaranteed-safe first-click opening; "no-guess" mode vs. allowing forced 50/50 spots; mine clustering/edge effects.

Generic Data Template
json 
{
  "puzzleType": "minesweeper", "gridSize": { "rows": 16, "cols": 16 },
  "mineCount": 40, "firstClickSafeRadius": 1, "requireNoGuess": true, "seed": 12345,
  "cellFacts": { "3,4": "attributeA -> valueB" }
}
// Not naturally data-driven; topic data attaches a fact to each revealed
// number cell, or requires clearing a region before an "answer" cell is shown.
Generation Algorithm
pseudocode 
1. Player (or generator) picks first-click cell c0.
2. Place mineCount mines uniformly at random over all cells EXCEPT c0 and its
   immediate neighbors (guarantees a safe opening).
3. Compute adjacency numbers for every non-mine cell.
4. If requireNoGuess:
     run a constraint-propagation solver from the flood-filled opening at c0:
       repeat: mark cells provably safe/mine via single-cell and
       subset/overlap constraint rules; reveal/flag them
       until no progress
     if entire board resolved -> accept board
     else -> reshuffle mines (or swap one ambiguous mine) and retry, up to N attempts
5. Output grid with mine positions + precomputed adjacency numbers
Edge Cases & Gotchas
  • Classic random placement frequently yields boards with a forced 50/50 late-game guess — must explicitly solver-validate "no-guess" claims.
  • Corner/edge cells have 3 or 5 neighbors instead of 8 — adjacency logic must handle boundaries separately.
  • The first click (and its opening) must never be a mine, or new players lose immediately.
  • High mine density near the safe-zone boundary can make the opening itself small/unsatisfying — tune density regionally.
12

Flow

Grid & Spatial Logic
Core Mechanic

A grid contains pairs of matching colored dots; the player draws one continuous, non-crossing path per color connecting its pair. In the standard "full" ruleset, every cell must be covered by exactly one path.

Cognitive Skill

Spatial path-planning with mutual exclusion — one wrong route always leaves an unreachable pocket.

Difficulty Levers

Grid size; number of color pairs; average/variance of path length; bottleneck density (narrow corridors forcing a specific route); whether full board coverage is required.

Generic Data Template
json 
{
  "puzzleType": "flow", "gridSize": { "rows": 8, "cols": 8 }, "requireFullCoverage": true,
  "pairs": [
    { "id": "pairA", "labelA": "itemA1", "labelB": "itemA2", "endpoints": [[0,0],[3,5]] },
    { "id": "pairB", "labelA": "itemB1", "labelB": "itemB2", "endpoints": [[7,0],[7,7]] }
  ]
}
// Topic data layers on by relabeling each color pair with a matched item
// pair (term/definition, synonym pairs, cause/effect).
Generation Algorithm
pseudocode 
1. Build a Hamiltonian path covering every cell of the r x c grid using a
   Warnsdorff-style heuristic (step to the unvisited neighbor with fewest
   onward options, randomized tie-break) with bounded restarts on dead ends.
2. Choose k (number of color pairs). Pick k-1 random cut points along the
   path, each segment length >= 2, splitting it into k contiguous runs.
3. For each run, its two endpoints become that color's dot pair; discard the
   interior (it becomes the hidden ground-truth solution).
4. Verify uniqueness: run a flow-solver (backtracking or SAT encoding of
   "each color = simple path between its dots, paths partition all cells")
   counting solutions with limit=2. If >1, re-cut the path and retry.
5. Output grid dims + endpoint pairs (+ topic labels).
Edge Cases & Gotchas
  • Partitioning one Hamiltonian path doesn't guarantee a unique solution — a different partition of the same cells can sometimes also satisfy the same endpoints; must solver-check.
  • Degenerate 1-cell segments (adjacent endpoints) are trivial — enforce a minimum segment length.
  • Obstacles/walls require re-verifying grid connectivity before the Hamiltonian-path step.
  • Too many colors for the grid size (short segments) or too few (long, nearly-solved segments) hurt difficulty balance.

Maze

Grid & Spatial Logic
Core Mechanic

A grid/graph of cells connected by open passages (walls blocking other connections) must be traversed from a start cell to an end cell, backtracking out of dead ends until reaching the goal.

Cognitive Skill

Graph/spatial traversal and backtracking — finding the one correct thread through a branching space.

Difficulty Levers

Grid size; dead-end density/branching factor (algorithm choice matters); solution path length relative to grid size; "braiding" (adding loops, trading uniqueness for fewer dead ends); visual obfuscation (isometric, fog-of-war).

Generic Data Template
json 
{
  "puzzleType": "maze", "gridSize": { "rows": 20, "cols": 20 },
  "algorithm": "recursiveBacktracker", "braidFactor": 0.0,
  "start": [0,0], "end": [19,19],
  "waypointItems": [{ "cell": [4,7], "content": "attributeA" }]
}
// Not naturally data-driven; topic data places items at junctions/dead-ends
// (collecting the correct-path ones spells an answer), or gates passages
// behind correctly-answered facts ("quiz-gated maze").
Generation Algorithm
pseudocode 
1. Model grid as cells with a wall on all 4 sides initially.
2. Randomized recursive backtracker:
     stack = [randomStartCell]; mark visited
     while stack not empty:
       current = stack.top
       neighbors = unvisited neighbors of current
       if neighbors empty: stack.pop()
       else:
         next = randomChoice(neighbors)
         removeWallBetween(current, next); mark next visited; stack.push(next)
   (alternative: randomized Prim's - grow a frontier set, connect to a random
    already-in-maze neighbor)
3. This produces a "perfect maze" - a spanning tree, exactly one path between
   any two cells.
4. Pick start/end via double-BFS: BFS from a random cell to find the farthest
   cell A, then BFS from A to find the farthest cell B -> use A, B as
   start/end to maximize solution path length.
5. (optional) Braiding: for braidFactor% of dead-ends, remove one extra wall
   to a random neighbor, eliminating that dead end but introducing a loop.
6. Output wall grid + start + end (+ solution path via BFS/DFS).
Edge Cases & Gotchas
  • Only an unbraided "perfect maze" guarantees a unique solution path — braiding trades uniqueness for fewer dead ends; decide upfront which is needed.
  • Recursive backtracking (long corridors) vs. Prim's (many short dead ends) materially changes difficulty, not just cosmetics.
  • Naive start/end choice (opposite corners) can produce a trivially short path — use the double-BFS farthest-cell trick.
  • Pre-placed obstacles require verifying full connectivity before generation, or some cells become unreachable islands.

Logic Grid Puzzle

Grid & Spatial Logic
Core Mechanic

N categories (e.g. names, colors, times) each with N items must be matched one-to-one. A list of clues (direct, negative, "same as," comparative, positional) lets the player eliminate impossible pairings, cross-referencing between categories until one full consistent assignment survives.

Cognitive Skill

Multi-step deductive elimination and cross-referencing across several linked relations.

Difficulty Levers

Number of categories; items per category; clue types used; ratio of clues given vs. minimum required; "indirection depth" of chained inferences; whether redundant clues are left in (easier) or pruned (harder).

Generic Data Template
json 
{
  "puzzleType": "logicGrid",
  "categories": [
    { "name": "categoryA", "items": ["itemA1","itemA2","itemA3"] },
    { "name": "categoryB", "items": ["itemB1","itemB2","itemB3"] },
    { "name": "categoryC", "items": ["itemC1","itemC2","itemC3"] }
  ],
  "solution": [
    { "categoryA": "itemA1", "categoryB": "itemB2", "categoryC": "itemC3" },
    { "categoryA": "itemA2", "categoryB": "itemB3", "categoryC": "itemC1" },
    { "categoryA": "itemA3", "categoryB": "itemB1", "categoryC": "itemC2" }
  ],
  "clues": [
    { "type": "direct", "text": "The row with itemA1 also has itemB2." },
    { "type": "negative", "text": "itemA2 does not go with itemC3." },
    { "type": "sameAs", "text": "Whoever has itemB3 also has itemC1." }
  ]
}
Generation Algorithm
pseudocode 
1. Randomly generate the ground-truth solution: N rows, one column per
   category, each column a random permutation of that category's items.
2. Instantiate a candidate clue pool by applying clue templates (direct,
   negative, sameAs, comparative-if-numeric, positional-if-ordered) to every
   valid pairing/triple implied by the solution.
3. Clue selection loop:
     workingSet = {}
     shuffle candidate pool
     for clue in candidate pool:
       add clue to workingSet
       if CSPsolve(categories, workingSet) yields exactly 1 solution: break
   (CSPsolve = row/column elimination + constraint propagation, falling back
    to backtracking search if propagation stalls)
4. Minimization pass: for each clue (random order), try removing it; if the
   remaining set still yields a unique solution, drop it permanently. Repeat
   until no clue can be dropped -> locally minimal, irredundant set.
5. Verify: exactly one solution, matches step-1 ground truth, no redundant
   clues remain.
6. Output categories + minimized clues (+ solution as answer key).
Edge Cases & Gotchas
  • Too few clues -> multiple valid solutions; too many/redundant -> trivial or unsatisfying — the add-until-unique-then-minimize loop avoids both.
  • A pure elimination solver may not be powerful enough to verify uniqueness if the puzzle needs hypothetical/contradiction reasoning — the verification solver must support limited case-branching.
  • Positional clues ("directly left of") are only valid for categories with inherent linear/ordinal structure — don't apply to unordered categories like colors.
  • Clue phrasing must use a fixed, well-defined vocabulary — freeform natural language risks multiple valid logical readings.

Pips

Grid & Spatial Logic
Research Note: Verified via web research: released by NYT Games in August 2025 as their first original logic puzzle.
Core Mechanic

The player places every tile from a full double-six domino set (28 tiles) onto a board whose cells are divided into color-coded regions. Each region carries a numeric rule (exact sum, all-equal, all-different, greater/less-than) over every pip value placed in it. A domino can straddle two regions, each half satisfying its own region's rule; solved when all tiles are placed and every rule holds.

Cognitive Skill

Combinatorial allocation under a fixed, shared inventory of numeric pieces — balancing simultaneous arithmetic constraints against a domino set that can't be reused.

Difficulty Levers

Board size/shape; mix of rule types per region; region size; how tight sum/threshold targets are relative to the feasible range; number of unconstrained "blank" cells; irregular board shapes with dead-end nooks.

Generic Data Template
json 
{
  "puzzleType": "pips",
  "boardCells": [
    { "coord": [0,0], "regionId": "R1" }, { "coord": [0,1], "regionId": "R1" },
    { "coord": [1,0], "regionId": "R2" }, { "coord": [1,1], "regionId": "blank" }
  ],
  "regions": [ { "id": "R1", "rule": "sum", "target": 7 }, { "id": "R2", "rule": "notEqual" } ],
  "dominoSet": "double-six-full",
  "regionFacts": { "R1": "attributeA corresponds to valueB" }
}
// Not naturally data-driven; topic content attaches a fact reveal to each
// region, or maps the 0-6 pip scale onto an ordered topic attribute.
Generation Algorithm
pseudocode 
1. Choose a board shape: connected polyomino with even cell count =
   2 x numDominoes (from a template library, or grown via randomized
   region-growth with connectivity checks).
2. Choose the domino subset (full double-six/28 for hard, smaller curated
   subset for easy/medium) - cell count must equal 2 x |dominoSet|.
3. Find a valid domino tiling of the board shape with the chosen set
   (perfect-matching/exact-cover backtracking over adjacent cell pairs) ->
   fixes the ground-truth placement.
4. Partition the board into regions (grow colored blobs of bounded size;
   deliberately let some cuts fall between a placed domino's two cells so it
   straddles two regions).
5. For each region, compute the real pip values of the ground-truth
   placement inside it, then choose a rule/target consistent with that
   ground truth (its actual sum, or equal/notEqual if it already holds, or a
   threshold with safe margin).
6. Uniqueness check: backtracking search over all placements of the exact
   domino multiset satisfying every region rule; count solutions (limit=2).
   if count != 1: tighten a rule or reshape a region, re-check.
7. Output board cells+regions, region rules, and domino inventory.
Edge Cases & Gotchas
  • Uniqueness search here means searching over placements of a fixed shared multiset of dominoes, not free digit assignment like Sudoku — a digit-style solver won't directly apply.
  • A "notEqual"/all-different region with more than 7 cells is automatically unsolvable, since pip values only range 0-6.
  • Region cell-count must be checked against the feasible sum range before assigning a "sum" target, or the region becomes mathematically impossible.
  • Symmetric or near-symmetric boards can admit multiple equivalent solutions (interchangeable dominoes swap without breaking rules) — the uniqueness solver must catch these.

3. Deduction & Social (6 Mechanics)

Connections

Deduction & Social
Core Mechanic

16 items are secretly partitioned into 4 groups of 4, each sharing a hidden theme. The player repeatedly selects 4 items they believe share a category; a correct guess reveals the theme, a wrong guess costs one of a limited number of mistakes. Categories are difficulty-ranked and color-coded, with deliberately seeded "red herrings" — items plausibly belonging to more than one category.

Cognitive Skill

Resolving competing categorical hypotheses under deliberate ambiguity — spotting which surface-plausible grouping is a trap.

Difficulty Levers

Number/strength of red herrings; semantic subtlety of the category rule (concrete vs. wordplay/pattern); number of allowed mistakes; surface homogeneity of items across categories; how loose vs. tight category definitions are.

Generic Data Template
json 
{
  "puzzleType": "connections", "gridSize": 16,
  "categories": [
    { "id": "categoryA", "theme": "shared trait A", "difficulty": 1, "items": ["itemA1","itemA2","itemA3","itemA4"] },
    { "id": "categoryB", "theme": "shared trait B", "difficulty": 2, "items": ["itemB1","itemB2","itemB3","itemB4"] },
    { "id": "categoryC", "theme": "shared trait C", "difficulty": 3, "items": ["itemC1","itemC2","itemC3","itemC4"] },
    { "id": "categoryD", "theme": "shared trait D (hardest/twist)", "difficulty": 4, "items": ["itemD1","itemD2","itemD3","itemD4"] }
  ],
  "displayGrid": ["itemC2","itemA1","itemD4","itemB3"]
}
Generation Algorithm
pseudocode 
1. Cluster dataset records by shared attribute/tag; keep only clusters with
   >=4 members.
2. Select 4 clusters as categories; rank difficulty by rule obscurity
   (literal category = easy, wordplay/pattern-based = hard).
3. For each category, pick exactly 4 items from its pool.
4. For every chosen item, test it against every OTHER category's defining
   predicate. IF item satisfies >1 category's rule exactly -> swap for a
   different pool member (true ambiguity is a hard fail).
5. OPTIONAL: for 1-2 items per category, pick ones with a surface-level
   (non-defining) similarity to an item in another category - manufactures a
   red herring without creating real ambiguity.
6. Flatten all 16 items, shuffle display order, store category->items-
   >difficulty as the answer key.
7. Brute-force/heuristic check: confirm no alternate 4x4 partition of the 16
   items also satisfies 4 coherent rules.
Edge Cases & Gotchas
  • An item genuinely qualifying for two categories under both rules simultaneously creates multiple valid solutions — must hard-reject at generation time.
  • Two categories ending up too similar to distinguish means players can't tell which group an item belongs to — merge/re-diversify themes.
  • Category difficulty ranking doesn't always match actual solver difficulty — needs a heuristic or test pass, not just author intent.
  • Small source datasets force a padded 4th category with weak members, producing an incoherent group.

Riddle

Deduction & Social
Core Mechanic

A single answer entity is described through figurative, metaphorical, or punning clues that are literally true but intentionally misdirect from the obvious interpretation; the solver must reframe non-literally to converge on one specific answer.

Cognitive Skill

The "aha" of lateral reframing — mentally shifting from literal to figurative interpretation to unlock an otherwise-hidden answer.

Difficulty Levers

Number of clues given; how abstract/personified the phrasing is; reliance on puns/homophones; strength of the false literal interpretation; obscurity of the answer; whether clues are ordered most-misleading to most-revealing.

Generic Data Template
json 
{
  "puzzleType": "riddle", "answer": "itemA",
  "sourceFacts": ["itemA belongs to categoryX", "itemA has propertyY", "itemA relates to itemB"],
  "clues": [
    { "text": "I am always near categoryX but never counted as one of them.", "device": "misdirection" },
    { "text": "The more of me you take, the more I leave behind.", "device": "paradox" }
  ],
  "difficulty": "medium"
}
Generation Algorithm
pseudocode 
1. Pick target "answer" record from dataset.
2. Extract 2-4 distinguishing facts/attributes (category, relation, property).
3. For each fact, transform the literal statement into figurative form using
   a device template: personification, paradox, category misdirection, or
   pun substitution (swap a key term for a homophone).
4. Order clues weakest/most-misleading -> strongest/most-revealing.
5. UNIQUENESS CHECK: verify no other dataset item satisfies ALL clues.
6. MISDIRECTION CHECK: verify at least one other dataset item plausibly
   satisfies the early clue(s) alone (proves genuine misdirection exists).
Edge Cases & Gotchas
  • Clue 1 alone already uniquely identifying the answer means no lateral thinking is required — collapses to trivia.
  • Pun/homophone devices don't generalize across languages or numeric/structured data — need a device fallback.
  • Two dataset items satisfying the full clue set equally creates an ambiguous riddle.
  • A metaphor too obscure to reverse-engineer even with the answer in hand is unsolvable, not just hard.

Likes/Dislikes

Deduction & Social
Research Note: Best modeled on inductive rule-guessing games — closest real analogs are Zendo (hidden-rule classification game) and the "Green Glass Door" party-game family.
Core Mechanic

A hidden rule/predicate classifies every item as "liked" or "disliked." The solver is shown pre-labeled examples and must induce the rule well enough to correctly predict the classification of new, unlabeled items.

Cognitive Skill

Hypothesis formation and testing against evidence — a compressed scientific-method loop.

Difficulty Levers

Rule complexity (single attribute vs. conjunction/negation of multiple); number of seeded examples; presence of "minimal pairs" vs. spurious correlations; size of the probe/test set; content-based vs. surface-based rules.

Generic Data Template
json 
{
  "puzzleType": "likesDislikes",
  "rule": { "description": "attributeX == valueA", "predicateField": "attributeX", "predicateValue": "valueA" },
  "examples": [
    { "item": "itemA", "liked": true }, { "item": "itemB", "liked": false },
    { "item": "itemC", "liked": true }, { "item": "itemD", "liked": false }
  ],
  "probeItems": ["itemE", "itemF", "itemG"]
}
Generation Algorithm
pseudocode 
1. Choose one dataset attribute (or a conjunction of two, for harder mode) as
   the hidden predicate.
2. Partition all items into liked/disliked sets; require both non-empty with
   enough members to seed examples + hold out probes.
3. Select example set prioritizing "minimal pairs": items identical except
   for the target attribute, labeled oppositely - blocks latching onto a
   wrong correlated attribute.
4. Hold out remaining items as probes for testing the induced rule.
5. SPURIOUS-CORRELATION CHECK: verify no OTHER single attribute also
   perfectly separates the shown example set. If one exists, add a
   counter-example that breaks the alternate hypothesis without breaking
   the true one.
6. For harder tiers, compose the rule from 2+ attributes (AND/OR/NOT) and
   repeat check 5.
Edge Cases & Gotchas
  • Shown examples can accidentally support more than one valid rule — must actively probe for and eliminate alternate hypotheses.
  • A rule based on incidental dataset artifacts (alphabetical order, ID parity) feels arbitrary rather than discoverable.
  • Insufficient members on one side of the partition prevents building a real example set.
  • If the item's label/text leaks the rule directly, induction becomes unnecessary.

Spot the Liar

Deduction & Social
Research Note: Closest real genres: Knights and Knaves logic puzzles and the party game Two Truths and a Lie.
Core Mechanic

A fixed number of speakers each make one statement about a shared ground-truth fact (or about each other); exactly one (or a known fixed count) is lying and all others are truthful. The solver cross-references statement content for contradictions to identify the liar.

Cognitive Skill

Constraint propagation on a small scale — testing each "who's lying" hypothesis until only one assignment stays contradiction-free.

Difficulty Levers

Number of speakers/statements; direct fact-checkable vs. self-referential meta-statements; number of true-but-suspicious red herrings; fixed vs. unknown liar count; whether ground truth must be inferred from true statements or is given externally.

Generic Data Template
json 
{
  "puzzleType": "spotTheLiar",
  "groundTruth": { "field": "attributeX", "value": "valueA" },
  "speakers": [
    { "id": "speakerA", "statement": "itemA has attributeX = valueA", "truthValue": true },
    { "id": "speakerB", "statement": "itemA has attributeX = valueB", "truthValue": false },
    { "id": "speakerC", "statement": "speakerB is telling the truth", "truthValue": false },
    { "id": "speakerD", "statement": "itemA does not have attributeX = valueB", "truthValue": true }
  ],
  "liarCount": 1, "solution": "speakerB"
}
Generation Algorithm
pseudocode 
1. Pick a verifiable ground-truth fact from the dataset.
2. Generate N speaker statements: (N - liarCount) true statements consistent
   with the fact; exactly `liarCount` false statement(s) that contradict the
   fact or contradict another true statement.
3. OPTIONAL: add meta-statements referencing another speaker's honesty to
   force chained deduction.
4. SOLVABILITY CHECK: enumerate all C(N, liarCount) liar assignments;
   simulate statement truth values under each; confirm EXACTLY ONE
   assignment is internally consistent. Regenerate if 0 or >1 found.
5. Shuffle speaker display order so the liar isn't positionally predictable.
6. Tune difficulty by making the false statement subtle and/or padding with
   extra true-but-suspicious statements.
Edge Cases & Gotchas
  • Statements not mutually exclusive enough leave multiple liar assignments consistent (ambiguous) or none (unsolvable) — verify computationally.
  • Genuine self-referential paradoxes ("I am lying") make the puzzle logically unsolvable, not just hard — exclude these.
  • An ambiguous ground-truth fact in the source data (a tie on the relevant attribute) breaks true/false scoring.
  • Red herrings indistinguishable from the actual lie reduce deduction to a coin flip.

Detective Interviews

Deduction & Social
Research Note: Closest real genres: narrative logic-grid mysteries (e.g. "5 Minute Mystery"-style case books) and classic logic grid puzzles applied to a crime scenario.
Core Mechanic

Several suspects/witnesses each give a statement containing testable claims; the solver cross-references claims against each other and a small set of hard facts, eliminating suspects whose story is inconsistent until exactly one remains implicated.

Cognitive Skill

Multi-constraint elimination — treating testimony as a mini logic grid solved via cross-referencing.

Difficulty Levers

Number of suspects; independent clues per suspect; ratio of direct lies to true-but-misleading statements; direct vs. externally-derived contradictions; narrative flavor obscuring the logical core; whether one clue eliminates multiple suspects at once.

Generic Data Template
json 
{
  "puzzleType": "detectiveInterview",
  "case": { "question": "Who is responsible for eventX?", "guiltyEntity": "suspectC" },
  "suspects": [
    { "id": "suspectA", "statement": "I was at locationX during timeY.",
      "claims": [{"field":"location","value":"locationX"},{"field":"time","value":"timeY"}] },
    { "id": "suspectB", "statement": "I was at locationZ, ask suspectA.",
      "claims": [{"field":"location","value":"locationZ"}] },
    { "id": "suspectC", "statement": "I was at locationX too, alone.",
      "claims": [{"field":"location","value":"locationX"}] }
  ],
  "facts": [{ "field": "location", "value": "locationX", "note": "the crime occurred here at timeY" }],
  "solution": "suspectC"
}
Generation Algorithm
pseudocode 
1. Pick the guilty entity and define ground-truth crime facts.
2. For each innocent suspect, generate a statement whose claims are fully
   consistent with an alibi that does NOT match the crime facts (their
   eliminating evidence).
3. For the guilty suspect, generate a statement that either directly
   contradicts an established fact, contradicts another corroborated
   statement, or leaves no valid alibi consistent with the crime facts.
4. Add independent corroborating clues/facts sufficient to eliminate every
   innocent suspect via at least one clue each.
5. OPTIONAL: inject a red herring - a suspect with suspicious-sounding but
   true and ultimately exculpatory statement.
6. VERIFY: run elimination logic over all suspects; confirm exactly one
   cannot be cleared. Regenerate/adjust clues if zero or multiple remain.
7. Order the narrative so no clue depends on later-introduced information.
Edge Cases & Gotchas
  • Insufficient clues to eliminate all-but-one suspect leaves multiple viable suspects (unsolvable/ambiguous ending).
  • A clue can accidentally clear the actual guilty suspect too, or wrongly implicate an innocent one.
  • A suspect's statement might be checkable against real dataset facts the generator didn't account for, creating unintended contradictions.
  • Red herrings indistinguishable from real eliminating evidence turn deduction into guesswork.

Pick a Room

Deduction & Social
Research Note: Closest real genres: escape-room "which door" elimination puzzles and classic mislabeled-sign puzzles (e.g. the three-boxes puzzle family).
Core Mechanic

N rooms/options each carry attributes and optionally a sign of unknown truth-value; a sequence of external clues progressively rules out rooms as candidates, applying each clue as a filter over the shrinking candidate set until exactly one valid choice remains.

Cognitive Skill

Sequential constraint filtering — a lightweight constraint-satisfaction solve giving steady incremental progress toward certainty.

Difficulty Levers

Number of rooms/options; number of clues relative to rooms; direct vs. conditional/indirect clues; whether signs can be true or false (adds a liar/truth-teller layer); order of clue revelation; redundancy between clues.

Generic Data Template
json 
{
  "puzzleType": "pickARoom",
  "rooms": [
    { "id": "room1", "attributes": {"attributeX":"valueA","attributeY":"valueB"}, "sign": "statement text", "signTruthValue": true },
    { "id": "room2", "attributes": {"attributeX":"valueC","attributeY":"valueD"}, "sign": "statement text", "signTruthValue": false },
    { "id": "room3", "attributes": {"attributeX":"valueE","attributeY":"valueF"}, "sign": "statement text", "signTruthValue": false }
  ],
  "clues": [
    "The correct room does not have attributeX = valueC.",
    "Exactly one room's sign is true, and it is not the correct room."
  ],
  "solution": "room1"
}
Generation Algorithm
pseudocode 
1. Pick the target correct room/option from the dataset.
2. Assign each room distinguishing attributes so every pair of rooms differs
   by at least one attribute.
3. Generate a pool of candidate clue templates, each a TRUE statement that
   eliminates one or more incorrect rooms without eliminating the correct one.
4. Greedily select clues from the pool (set-cover style) until every
   incorrect room is eliminated by at least one selected clue AND the
   correct room satisfies every selected clue.
5. IF using signs: fix a meta-rule (e.g. "exactly one sign is true") and
   generate each room's sign text consistent with it; include the meta-rule
   as a clue.
6. Order clues broad -> narrow for readability (or reverse to raise difficulty).
7. VERIFY: brute-force/constraint-check all rooms against all clues; confirm
   exactly one room satisfies every clue.
Edge Cases & Gotchas
  • Under-determined clue sets leave more than one room surviving all clues — no unique answer.
  • Over-determined/contradictory clue sets leave zero rooms satisfying every clue — unsolvable.
  • A logically redundant clue is harmless as flavor but should be flagged so it isn't miscounted as load-bearing.
  • Adding a sign/truth-value layer can accidentally create a liar's-paradox sign that can't be consistently assigned true or false.

4. Math & Physical (7 Mechanics)

System of Equations

Math & Physical
Core Mechanic

The solver is given N equations relating N unknowns (typically linear) and must isolate each unknown via substitution or elimination. Usually dressed up as a word problem, cryptarithmetic grid, or symbolic clue set — underneath, always a solvable linear (or occasionally polynomial) system.

Cognitive Skill

Algebraic deduction — combining partial information from multiple constraints to pin down values no single clue reveals alone.

Difficulty Levers

Number of unknowns; coefficient size/messiness; equations shown directly vs. hidden in a narrative; degree (linear vs. nonlinear); number of redundant clues; whether unknowns must be integers.

Generic Data Template
json 
{
  "facts": [
    {"id":"F1","label":"fact label A","value":7},
    {"id":"F2","label":"fact label B","value":4},
    {"id":"F3","label":"fact label C","value":12}
  ],
  "num_unknowns": 3,
  "equations": [
    {"coeffs":[2,1,-1],"vars":["F1","F2","F3"],"result":9},
    {"coeffs":[1,-1,2],"vars":["F1","F2","F3"],"result":27},
    {"coeffs":[-1,3,1],"vars":["F1","F2","F3"],"result":23}
  ],
  "presentation": "word_problem"
}
Generation Algorithm
pseudocode 
1. Pull n numeric facts from the dataset as the "answer key" x = [x1..xn]
   (or invent them if the dataset lacks enough numbers).
2. Generate an n x n integer coefficient matrix A with det(A) != 0 (unique
   solution), preferably det(A) in {1,-1} or small (clean intermediate
   fractions), and no row a scalar multiple of another (redundant clue).
3. Compute b = A * x -> these become the equations' right-hand sides.
4. Verify: solve A*x' = b via elimination, assert x' == x exactly (round-trip
   check).
5. Render each row as a raw equation, a templated word-problem sentence, or
   a cryptarithmetic-style substitution.
6. Optionally shuffle/relabel unknowns and add 1 harmless redundant
   (dependent) equation as a "check" clue, never as one of the n solving
   equations.
Edge Cases & Gotchas
  • Singular or near-singular A gives no solution or infinitely many — always check det(A) != 0 before rendering.
  • Large/random coefficients produce ugly non-integer or huge solutions — constrain the coefficient range and verify the solution stays within a "nice" bound.
  • Two equations that are linear combinations of each other feel like two clues but convey only one constraint — rank-check the matrix, not just count rows.
  • Natural-language phrasing in word problems can accidentally imply a different equation than intended — re-derive the equation from the sentence template rather than writing sentences freehand.

Train Problem

Math & Physical
Core Mechanic

Two (or more) movers travel at constant rates from given starting positions/times; the solver applies distance = rate x time to find when/where they meet, one overtakes the other, or their gap closes to a target value. A narratively-dressed 2-variable system of equations.

Cognitive Skill

Translating a real-world scenario into rate/time proportional reasoning.

Difficulty Levers

Scenario type (opposite-direction meeting, same-direction catch-up, staggered departures); number of movers; clean integer vs. simple-fraction answers; added realism (unit conversions, rest stops); whether the question asks for time, location, or gap-at-time-T.

Generic Data Template
json 
{
  "movers": [
    {"id":"A","label":"mover A","start_position":0,"rate":12,"start_time":0},
    {"id":"B","label":"mover B","start_position":180,"rate":-8,"start_time":0}
  ],
  "unit": {"position":"units","time":"minutes"},
  "scenario": "opposite_direction_meet",
  "question": "at_what_time_do_they_meet"
}
// Generalizes to any two linearly-accumulating quantities (e.g. two
// savings accounts growing at fixed rates, two readers finishing pages/day).
Generation Algorithm
pseudocode 
1. Choose scenario type.
2. Pick a target answer t* (clean integer, or simple fraction).
3. Work backward:
   - opposite direction: pick rates r1, r2 and gap D such that
     D / (r1 + r2) = t*
   - same direction/catch-up: pick rates r1 > r2 and head-start such that
     (head_start * r2) / (r1 - r2) = t*
4. Verify r1 != r2 for meeting scenarios.
5. Verify t* > 0 and all derived distances/positions are physically sensible
   (non-negative, realistic magnitude for the chosen unit).
6. Render as narrative using dataset labels/units in place of "train."
Edge Cases & Gotchas
  • Equal rates in a same-direction chase means the gap never closes (no solution); check for meeting vs. overtaking explicitly for opposite-direction cases.
  • Rounding the target time to a "nice" number AFTER picking rates (forward generation) often produces repeating decimals — always generate backward from a clean t*.
  • Negative or zero derived distances/head-starts are nonsensical and must be rejected.
  • More than 2 movers makes "who meets whom first" non-linear — compute all pairwise meeting times explicitly and pick the intended one.

Liquid Transfers

Math & Physical
Research Note: Fixed-mechanic puzzle — no natural "any topic" data schema for the mechanic itself. Topic data layers on as flavor: relabel jugs/target with topic quantities, or attach a trivia fact to each jug revealed when used correctly.
Core Mechanic

Given jugs of fixed, unmarked capacities, the solver may fill a jug, empty a jug, or pour from one into another until the source is empty or destination is full, aiming to reach an exact target volume in some jug (or the total).

Cognitive Skill

State-space search and forward planning — visualizing several moves ahead since intermediate states look nothing like the goal.

Difficulty Levers

Number of jugs; capacities chosen (their GCD relative to target); minimum moves in the optimal solution; whether an unlimited source/drain exists; a distractor jug that isn't needed.

Generic Data Template
json 
{
  "jug_capacities": [3, 5], "target": 4, "target_container": "either",
  "unlimited_source_available": true,
  "flavor_labels": {"jug_0": "container A", "jug_1": "container B"},
  "max_moves_allowed": null
}
Generation Algorithm
pseudocode 
1. Choose 2+ jug capacities [c1, c2, ...].
2. Compute g = gcd(c1, c2, ...).
3. Choose target such that target % g == 0 AND target <= max(capacities)
   (single-jug reading) OR target <= sum(capacities) (combined reading).
4. Run BFS/DFS over the full state space (each state = tuple of current fill
   levels) to confirm the target is reachable AND record the optimal move
   count.
5. If optimal move count is too low/high for the desired difficulty, re-roll
   capacities/target and repeat step 4.
6. Store the verified solution path for hint generation / solvability proof.
Edge Cases & Gotchas
  • A target not a multiple of gcd(capacities) is mathematically unreachable no matter how it's played — must be checked before publishing.
  • A target achievable only in the combined volume of two jugs rather than a single jug requires deciding up front which win condition applies.
  • Non-coprime-in-a-useful-way capacities can make the puzzle trivial or require far more moves than intended — BFS-verify move count, don't assume.
  • Naive generators often allow partial pours, which trivializes almost every instance — enforce "pour until source empty OR destination full" exactly.

Coin Breakdown

Math & Physical
Core Mechanic

Given a target amount and a set of denominations, the solver finds the minimum number of "coins" summing exactly to the target, or enumerates/counts the distinct ways to reach it — the classic coin-change combinatorics/DP problem.

Cognitive Skill

Combinatorial optimization — deciding when greedy (largest-first) reasoning works and when it silently fails.

Difficulty Levers

Canonicity of the denomination set (canonical = greedy-safe; non-canonical requires real DP); target magnitude; unlimited vs. limited supply per denomination; "min coins" vs. "count all ways" mode; presence of a value-1 denomination.

Generic Data Template
json 
{
  "denominations": [
    {"label":"unit A","value":25},{"label":"unit B","value":10},
    {"label":"unit C","value":4},{"label":"unit D","value":1}
  ],
  "target": 63, "mode": "min_count", "supply_per_denomination": "unlimited"
}
Generation Algorithm
pseudocode 
1. Choose a denomination set: canonical (greedy-safe) for easy mode, or
   intentionally non-canonical for hard mode (e.g. {1,3,4}: greedy(6)=4+1+1
   (3 coins) but optimal=3+3 (2 coins)).
2. Ensure a value-1 (or dataset-min) denomination exists, OR verify the
   target is expressible via a reachability DP over 0..target.
3. Pick target: large enough to require multiple denominations; for "count
   ways" mode, cap it so the combination count stays tractable (e.g. <=50).
4. Run DP to compute the true optimal min-coin count and/or full ways-count;
   also compute the greedy result to detect divergence.
5. If mode is "min_count," score against the DP-verified optimum, not
   greedy, unless the denomination set is canonical.
Edge Cases & Gotchas
  • Missing a value-1/smallest-unit denomination can make many targets flat-out unreachable — always DP-check reachability.
  • Confusing the greedy answer with the true optimal for non-canonical sets — decide explicitly which is scored, and verify with DP.
  • Limited supply per denomination changes the DP to a bounded-knapsack variant — an unlimited-supply solver will overcount.
  • "Count ways" mode can combinatorially explode for large targets/many denominations — bound target size or denomination count.

Solitaire (Klondike)

Math & Physical
Research Note: Not inherently data-driven — a pure fixed-mechanic game. Topic data layers on only by relabeling the 52 cards: partition topic items into 4 categories of 13 strictly-ranked items, 2 assigned each "color," so the alternating-color tableau rule still functions.
Core Mechanic

A 52-card deck is dealt into 7 tableau columns (only the top card face-up); tableau piles build downward in alternating colors, only a King may fill an empty column, foundations build upward by suit from the Ace. The player draws from stock to waste and wins by moving all 52 cards to the foundations.

Cognitive Skill

Sequential planning under partial information — deciding which face-down cards to uncover and in what order.

Difficulty Levers

Draw-one vs. draw-three; number of allowed stock redeals; the specific shuffle/seed (some deals are provably unsolvable); scoring mode; time/move limits.

Generic Data Template
json 
{
  "deck_seed": 481932, "draw_mode": "turn_one", "redeals_allowed": "unlimited",
  "topic_relabeling": {
    "suits": [
      {"name":"Category A","color":"red","ranks":["item1","item2","item13"]},
      {"name":"Category B","color":"black","ranks":["item1"]},
      {"name":"Category C","color":"red","ranks":["item1"]},
      {"name":"Category D","color":"black","ranks":["item1"]}
    ]
  }
}
Generation Algorithm
pseudocode 
1. Seed an RNG (store the seed for reproducibility/sharing).
2. Shuffle the 52-card deck.
3. Deal columns 1..7 with i cards each, last card face-up, rest face-down;
   remaining 24 cards -> stock.
4. Set draw_mode and redeal policy.
5. (Recommended) Run a Klondike solver against the seed BEFORE publishing to
   confirm winnability - a meaningful fraction of random deals are provably
   unsolvable; reject/reshuffle seeds that fail.
6. If topic-relabeling is used, map the 4 suits and 13 ranks onto the
   generated deck positions after dealing.
Edge Cases & Gotchas
  • Not every random deal is solvable — publishing "any shuffle" without a solver check occasionally hands players an impossible puzzle.
  • Turn-three mode is meaningfully harder/less solvable than turn-one — difficulty tuning must account for draw mode, not just the shuffle.
  • Topic relabeling breaks if a category doesn't have exactly 13 cleanly-ranked items or the 4 categories can't split into 2 balanced color groups.
  • A full Klondike solver is computationally expensive — precompute and cache a pool of verified-solvable seeds rather than solving on every request.

Spot the Difference

Math & Physical
Research Note: Not inherently data-driven for the image itself. Topic data layers on as an annotation/reward: each difference is tagged with a fact/question revealed once located, or the base scene is a topic-relevant diagram where one specific label is the altered element.
Core Mechanic

Two versions of the same image differ in a fixed number of discrete, localized edits (object added/removed/moved/resized/rotated, or color/pattern changed). The solver visually scans and marks each difference; solved when all N are found.

Cognitive Skill

Sustained visual attention and comparative perception — noticing what changed versus what merely looks similar.

Difficulty Levers

Number of differences; subtlety of each edit; overall image complexity/clutter; time limit; whether differences are clustered or spread out; camouflage against busy backgrounds.

Generic Data Template
json 
{
  "base_image": "scene_A.png", "modified_image": "scene_B.png",
  "differences": [{
    "id": "diff_1", "region": {"x":120,"y":340,"radius":25}, "type": "color_change",
    "associated_fact": {"label":"fact tied to this element","value":"..."}
  }],
  "difficulty": {"num_differences": 7, "min_spacing_px": 60, "time_limit_sec": 120}
}
Generation Algorithm
pseudocode 
1. Start from (or generate) base image A.
2. Choose k differences to introduce.
3. For each difference, pick a region fully inside image bounds and at least
   min_spacing_px from every other chosen region (prevents visual merging).
4. Apply the edit (recolor/remove/add/translate/scale/rotate) to produce
   image B.
5. Programmatically diff A vs B (pixel/structural diff) to auto-generate the
   ground-truth manifest - never hand-track coordinates, since an edit can
   have unintended side effects (e.g. moving an object reveals background
   behind it, creating an unplanned second difference).
6. Validate the manifest has exactly k distinct, non-overlapping regions;
   adjust and re-diff if the count is off.
7. Optionally attach topic facts to each verified region.
Edge Cases & Gotchas
  • Edits placed too close together get perceived (and auto-detected) as a single difference — enforce minimum spacing.
  • Edits near image edges can be cropped or barely visible — exclude a border margin from candidate regions.
  • An edit can have unintended side effects, silently changing the true difference count — always verify with automated image diff, not the edit list.
  • Overly subtle edits may be mathematically present but practically imperceptible — set a minimum perceptual-difference threshold.

Word Tetris (Wordtris)

Math & Physical
Research Note: Verified against the original 1991 Spectrum HoloByte game Wordtris.
Core Mechanic

Single letter tiles fall one at a time into a 9-wide well; the player positions each tile to complete words of 3+ letters, readable horizontally or vertically (overlaps allowed). Completed words clear. Special tiles include a wildcard "?" and an eraser; completing a designated "magic word" clears the entire well for a bonus.

Cognitive Skill

Real-time vocabulary recall combined with spatial packing under time pressure — Tetris's falling-piece planning fused with a word game's lexical search.

Difficulty Levers

Fall speed; grid width/height; letter-frequency distribution of the falling queue; minimum word length required to score; frequency of wildcard/eraser tiles; length/rarity of the magic word.

Generic Data Template
json 
{
  "word_bank": [
    {"word":"TERM1","hint":"hint1"},{"word":"TERM2","hint":"hint2"},{"word":"TERM3","hint":"hint3"}
  ],
  "magic_word": "TERM3",
  "grid": {"width": 9, "height": 10, "water_rows": 5},
  "fall_speed": "level-dependent",
  "special_tile_rates": {"wildcard": 0.05, "eraser": 0.03},
  "min_clear_length": 3
}
Generation Algorithm
pseudocode 
1. Take the topic word list; filter to words that fit the grid dimensions
   (length <= max(width, height)).
2. Build a letter-frequency table weighted toward letters in the word bank
   (so the falling queue makes those words completable), while still
   including enough common filler letters to keep the board playable.
3. Choose one word (ideally longer/central to the topic) as the magic word.
4. Seed the falling-tile queue by sampling from the frequency table, with a
   periodic "guarantee" pass ensuring each target word's required letters
   appear within a reasonable number of drops (simulate to check).
5. Insert wildcard/eraser tiles at the configured rates.
6. Set fall speed and grid size per difficulty tier.
7. Simulate a few playthroughs (or a solver bot) to confirm target words are
   completable often enough at the chosen difficulty before publishing.
Edge Cases & Gotchas
  • A target word longer than the grid's width or height can never be placed — filter these out during word-bank ingestion.
  • Skewing the frequency table too heavily toward rare letters starves common connector letters and makes the board unplayable — always blend in baseline common-letter frequencies.
  • Without simulating letter arrival, a word requiring a rare letter may be statistically unreachable within a normal game length.
  • A magic word chosen too long relative to well capacity makes the bonus condition nearly unattainable — bound its length relative to grid height/width.
